# معیارهای پذیرش (ACCEPTANCE CRITERIA) — AVA Native

هر فاز فقط وقتی «تکمیل‌شده» است که همهٔ معیارهایش با اجرای واقعی اثبات شود. برچسب‌ها: `AC-n` · روش اثبات: تست خودکار / خروجی فایل / اجرای دستور.

## فاز ۰ — ممیزی
- AC0.1: پنج سند فاز صفر موجود و هم‌خوان با وضعیت واقعی مخزن باشند.
- AC0.2: هر جزء دارای وضعیت KEEP/REFACTOR/REPLACE/REMOVE/INVESTIGATE باشد.
- AC0.3: مجوز تک‌تک اجزا و وابستگی‌ها ثبت شده باشد؛ اجزای ناسازگار با تجاری مشخص شده باشند.

## فاز ۱ — موتور زبان فارسی
- AC1.1: نرمال‌سازی کاراکتر (عربی→فارسی، حذف نویسهٔ نامرئی، نیم‌فاصله) — تست.
- AC1.2: اعداد صحیح/اعشاری/ترتیبی/درصد/واحد → گفتار — تست.
- AC1.3: تاریخ شمسی/میلادی و ساعت/دقیقه → گفتار — تست.
- AC1.4: بخش‌بندی جمله و تقسیم متن طولانی با حفظ ترتیب — تست.
- AC1.5: تشخیص متن ترکیبی فارسی/انگلیسی و حفظ کلمات لاتین — تست.
- AC1.6: تلفظ واژگانی قابل توسعه (lexicon) + قواعد — تست.
- AC1.7: متن‌های ترکیبی و علائم متعدد، خروجی پایدار — تست.

## فاز ۲ — معماری عصبی اختصاصی
- AC2.1: سند طراحی با مقایسهٔ گزینه‌ها و دلیل انتخاب.
- AC2.2: پیاده‌سازی اصلی (نه کپی) با forward و backward سبز.
- AC2.3: پشتیبانی طراحی‌شده از single/multi-speaker و streaming (در سطح معماری + کد).

## فاز ۳ — دیتاست
- AC3.1: manifest schema + loader — تست.
- AC3.2: اعتبارسنجی صوت (فرمت/sr/کانال/طول/سکوت/نویز) — تست با WAV ساختگی.
- AC3.3: split قطعی و نسخه‌بندی — تست.
- AC3.4: ثبت منشأ/رضایت/مجوز در متادیتا — schema + تست.

## فاز ۴ — آموزش
- AC4.1: trainer با checkpoint + resume واقعاً اجرا شود (کاهش loss روی smoke).
- AC4.2: validation و logging قابل مشاهده.
- AC4.3: export مدل پس از آموزش.
- AC4.4: نیازمندی‌های آموزش واقعی (GPU/داده) مستند شود؛ مدل smoke هرگز مدل نهایی معرفی نشود.

## فاز ۵ — runtime
- AC5.1: synthesize/synthesize_stream/batch/stop/load/unload/list_voices/get_model_info — تست.
- AC5.2: خروجی WAV واقعی با sr/کانال مشخص.
- AC5.3: رابط مستقل از معماری مدل (پلاگین).

## فاز ۶ — صداها
- AC6.1: registry + پروفایل + متادیتا — تست.
- AC6.2: ابزار تست کیفیت prompt — اجرا.
- AC6.3: صداهای اختصاصی فقط در صورت دادهٔ مجاز؛ وگرنه وضعیت «مشروط» ثبت شود.

## فاز ۷ — پلتفرم‌ها
- AC7.1: API با تست (synthesis/voices/health + محدودیت اندازه).
- AC7.2: CLI با زیرفرمان‌ها — اجرا.
- AC7.3: Web RTL فارسی — فایل واقعی + تست اتصال mock.
- AC7.4: export ONNX واقعی و اجرا با onnxruntime.
- AC7.5: Windows/Android: کد cross-platform + اسناد؛ آزمون روی دستگاه واقعی = تحویل‌نشده (ثبت صادقانه).

## فاز ۸ — Raya
- AC8.1: قرارداد کامل (متن/صدا/سرعت/جریان/وضعیت/توقف/خطا) + مثال‌ها.
- AC8.2: AVA هیچ وابستگی به Raya نداشته باشد.

## فاز ۹ — امنیت و کیفیت
- AC9.1: تست‌های امنیتی (اندازه ورودی، مسیر فایل، یونیکد، مصرف حافظه) سبز.
- AC9.2: کل pytest سبز + شمارش.
- AC9.3: بنچمارک RTF/حافظه ثبت‌شده.
- AC9.4: ۱۲ سناریوی فارسی مشخص‌شده پوشش داده شود.

## تحویل نهایی
- AC10.1: موتور مستقل و مستند؛ AC10.2: منشأ/مجوز همهٔ اجزای توزیع‌شده مشخص؛ AC10.3: مدل اختصاصی فقط پس از آموزش واقعی؛ AC10.4: هر قابلیت آزمایش‌نشده «آماده» معرفی نشود.
