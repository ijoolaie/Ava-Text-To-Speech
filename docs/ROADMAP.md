## فاز ۱ — تثبیت هسته مستقل (12%) · وضعیت: 85%

**انجام‌شده:** معماری نهایی AVA-N1 تعیین، پیاده‌سازی و تست شده (`docs/NEURAL_ARCHITECTURE.md`, `ava/models/native/`)؛ Legacy کاملاً از هسته تفکیک شده (آداپتور اختیاری، غیرپیش‌فرض، غیرتجاری — `ava/runtime/backends.py`)؛ قرارداد ورودی/خروجی تثبیت (WAV 24kHz mono PCM-16، mel استاندارد، API پایدار).
**باقی‌مانده:**
- [ ] پروفایل بیلد «محصول»: بیلد بدون legacy (بدون `weights/` و آداپتور) — اسکریپت packaging
- [ ] تصمیم کارفرما دربارهٔ وزن‌های NC در git history (untrack یا حذف)
- [ ] قفل نسخهٔ قراردادها در `pyproject` (version + API tags)
**وابستگی‌ها:** بدون وابستگی خارجی.
**معیار پذیرش:** بیلد محصول فقط با باندل AVA-N1 از سورس تا خروجی صوت کار کند و هیچ مسیر کد به legacy وابسته نباشد؛ تست‌های هسته سبز.

## فاز ۲ — آماده‌سازی داده فارسی (15%) · وضعیت: 35%

**انجام‌شده:** کل ابزار دیتاست (manifest با منشأ/مجوز/رضایت، اعتبارسنجی صوت، قطعه‌بندی، split قطعی، fingerprint — `training/datasets/`، `docs/DATASET_PIPELINE.md`)؛ منابع مجاز تعیین‌شده: ضبط اختصاصی با رضایت‌نامه + Mozilla Common Voice-fa (CC0-1.0).
**باقی‌مانده:**
- [ ] تأمین ≥۵ ساعت گفتار تمیز (v0) و ثبت منشأ/مجوز برای همهٔ قطعات
- [ ] هم‌ترازی متن-صوت (MFA فارسی یا ASR-based) → `durations` در manifest
- [ ] پاک‌سازی نهایی و تقسیم train/val/test نهایی + گزارش کیفیت
- [ ] فرم رضایت‌نامهٔ گویندگان (`data/raw/consents/`)
**وابستگی‌ها:** دسترسی کارفرما به گوینده/دیتاست؛ GPU برای latentcache لازم نیست.
**معیار پذیرش:** manifest نهایی با fingerprint ثبت‌شده، صفر قطعهٔ بدون منشأ/مجوز، گزارش اعتبارسنجی با صفر خطای بحرانی.

## فاز ۳ — آموزش مدل اختصاصی (25%) · وضعیت: 45%

**انجام‌شده:** Pipeline آموزش کامل و اثبات‌شده (trainer با checkpoint/resume/validation/logging/export — smoke واقعی ۳۰۰ گام CPU: loss 19.32→0.141، val 0.196، `docs/TRAINING_GUIDE.md`)؛ ذخیره/بازیابی وزن تست‌شده.
**باقی‌مانده:**
- [ ] آموزش واقعی روی GPU با دادهٔ فاز ۲ (برآورد v0: ۲-۴ روز روی RTX 4090)
- [ ] تولید **اولین نمونهٔ صوتی واقعی از وزن اختصاصی AVA** (نه legacy، نه fixture)
- [ ] انتخاب/آموزش vocoder عصبی (v1 Griffin-Lim فقط صحت‌سنجی است)
- [ ] ثبت منحنی آموزش و گزارش ارزیابی اولیه
**وابستگی‌ها:** فاز ۲ کامل؛ GPU (سرور کارفرما یا کلود).
**معیار پذیرش:** checkpoint اختصاصی + WAV قابل شنیدن تولیدشده از آن + ثبت نمونه در `samples/`.

## فاز ۴ — کیفیت و چندصدایی (15%) · وضعیت: 45%

**انجام‌شده:** کیفیت زبانی بالا (نرمال‌سازی/اعداد/تاریخ/ساعت/واحد — ۴۴ تست)؛ جدول مکث و سرعت (prosody پایه)؛ زیرساخت چندصدایی با الزام رضایت‌نامه (`ava/voices/`).
**باقی‌مانده:**
- [ ] بهبود تلفظ: G2P/واژگان تلفظ گسترده + تعیین تلفظ بر پایهٔ خطای واقعی مدل
- [ ] prosody طبیعی: کنترل مکث/آهنگ با durations واقعی پس از هم‌ترازی
- [ ] پردازش متن محاوره‌ای (نگاشت محاوره→رسمی)
- [ ] آموزش ≥۳ صدای مستقل از دادهٔ مجاز + پذیرش کیفیت هر صدا
**وابستگی‌ها:** فاز ۳ (مدل آموزش‌دیده)، فاز ۲ (دادهٔ چندگوینده).
**معیار پذیرش:** MOS ≥ 3.5 روی ۲۰ نمونه با ≥۵ شنوندهٔ فارسی؛ WER ≤ ۲۵٪ با ASR فارسی؛ سه voice_id مستقل از یک runtime قابل انتخاب.

## فاز ۵ — Runtime آفلاین (13%) · وضعیت: 70%

**انجام‌شده:** استنتاج کاملاً آفلاین روی CPU (بدون هیچ دانلود/سرویس بیرونی)؛ مدیریت خطا و ورودی نامعتبر تست‌شده (۹ تست امنیت/کیفیت)؛ خروجی استاندارد WAV؛ API پایدار با قرارداد Raya؛ RTF 0.93 اندازه‌گیری‌شده.
**باقی‌مانده:**
- [ ] بهینه‌سازی حافظه/سرعت روی باندل واقعی (پس از فاز ۳) + کوانتیزاسیون اختیاری
- [ ] streaming فریم‌محور داخل مدل (v2) برای تعامل صوتی زنده
- [ ] پروفایل حافظه/باتری برای Android
**وابستگی‌ها:** فاز ۳ برای باندل واقعی.
**معیار پذیرش:** استنتاج آفلاین کامل بدون اینترنت روی CPU متعارف؛ RTF ≤ 1 برای جملهٔ معمول؛ tests/runtime+security سبز.

## فاز ۶ — بسته‌بندی و پلتفرم‌ها (12%) · وضعیت: 40%

**انجام‌شده:** API + CLI + وب فارسی RTL کارا؛ export ONNX با صحت‌سنجی (opset-17)؛ راهنمای Windows و Android؛ `ava-cli` با ۵ زیرفرمان.
**باقی‌مانده:**
- [ ] بستهٔ قابل استفادهٔ Windows (wheel/installer + تست نصب واقعی)
- [ ] اتصال و اجرای واقعی Android (ONNX Runtime Mobile + JNI mel→PCM + benchmark دستگاه)
- [ ] Model Manager یکپارچه در CLI (دانلود/حذف/لیست باندل‌ها با checksum)
- [ ] نمونهٔ کاربردی (examples/) برای API و CLI
**وابستگی‌ها:** فاز ۳ (باندل واقعی برای توزیع)؛ دستگاه ویندوزی/اندرویدی کارفرما برای تست.
**معیار پذیرش:** نصب روی Windows تمیز با یک دستور؛ سنتز آفلاین روی دستگاه اندرویدی با RTF ثبت‌شده.

## فاز ۷ — انتشار نهایی (8%) · وضعیت: 25%

**انجام‌شده:** مستندات فنی گسترده (معماری/آموزش/دیتاست/ارزیابی/Raya)؛ مجوزها و NOTICE کامل؛ README دوزبانه.
**باقی‌مانده:**
- [ ] مستندات کاربری نهایی (نصب/استفادهٔ محصول، نه فقط توسعه)
- [ ] نسخه‌بندی رسمی (v1.0.0) + بستهٔ انتشار امضاشده
- [ ] نمونه‌های صوتی واقعی از وزن اختصاصی
- [ ] اعلام محدودیت‌های شناخته‌شده در README
**وابستگی‌ها:** همهٔ فازهای قبلی.
**معیار پذیرش:** بستهٔ انتشار قابل نصب از صفر روی ماشین تمیز + مستندات بدون «قابلیت مستندشدهٔ پیاده‌ناشده».

## نکتهٔ کلیدی راهبردی

هستهٔ مستقل هم‌اکنون به‌صورت کد تست‌شده موجود است؛ **گلوگاه واحد پروژه «دادهٔ مجاز + GPU» است** (فاز ۲ و ۳). پس از آموزش واقعی، فازهای ۴-۶ عمدتاً تنظیم و بسته‌بندی‌اند، نه ساخت از صفر — زیرا runtime/API/صداها از همان ابتدا پشت قرارداد پلاگین‌پذیر طراحی شده‌اند و مستقل از معماری‌اند.
