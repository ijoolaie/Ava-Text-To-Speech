# نقشهٔ بازسازی (REBUILD ROADMAP) — AVA Native

هدف: تبدیل مخزن فعلی به **AVA Native** — موتور گفتار فارسی مستقل، قابل استفادهٔ تجاری (پس از آموزش روی دادهٔ مجاز)، با runtime ماژولار برای Windows/Android/Web و اتصال‌پذیر به Raya-Hybrid.

اصل راهنما: هیچ جزء دارای مجوز ناسازگار با تجاری، به‌عنوان وابستگی محصول باقی نمی‌ماند؛ هر ادعای «انجام‌شده» با تست واقعی قابل اثبات است.

## فازها و خروجی‌های قابل بررسی

| فاز | محتوا | خروجی قابل اثبات | وزن پیشرفت |
| --- | --- | --- | --- |
| ۰ ممیزی | audit کامل + اسناد | ۵ سند docs/ + این نقشه | 5% |
| ۱ موتور زبان فارسی | ماژول‌های normalization/numbers/datetime/segmentation/chunking/pronunciation/language_detect/prosody | کد + تست خودکار سبز | 10% |
| ۲ معماری عصبی اختصاصی | طراحی + پیاده‌سازی `ava/models/native/` | سند NEURAL_ARCHITECTURE + تست forward/backward سبز | 10% |
| ۳ پایپ‌لاین دیتاست | manifest، validate، split، منشأ و رضایت | کد + تست با دادهٔ ساختگی + سند DATASET_PIPELINE | 15% |
| ۴ آموزش مدل اختصاصی | trainer با checkpoint/resume/val/export | smoke training واقعی روی CPU (کاهش loss + checkpoint + resume) + سندهای آموزش/ارزیابی | 25% |
| ۵ runtime | load/unload/synthesize/stream/batch/WAV/stop | تست‌های runtime + تولید WAV واقعی | 10% |
| ۶ سیستم صدا | registry، پروفایل، متادیتا، کیفیت | کد + تست (صداهای اختصاصی = مشروط به دادهٔ مجاز) | 10% |
| ۷ پلتفرم‌ها | API (FastAPI)، CLI، Web RTL، مسیر ONNX/Android، Windows | تست API + UI + export ONNX واقعی + اسناد پلتفرم | 10% |
| ۸ اتصال Raya | قرارداد API پایدار | سند RAYA_HYBRID_INTEGRATION (+ همان API تست‌شده) | 2.5% |
| ۹ امنیت و کیفیت | تست‌های امنیتی/کارایی/رجسیون + بنچمارک | pytest کامل سبز + نتایج بنچمارک | 2.5% |

## ترتیب اجرا و وابستگی‌ها

```
۰ → ۱ → ۲ → ۳ → ۴ → ۵ → ۶ → ۷ → ۸ → ۹
```
فاز ۳ و ۴ روی خروجی فاز ۱ و ۲ سوارند؛ فاز ۵ با هر دو مدل (native smoke + آداپتور Legacy اختیاری) تست می‌شود تا رابط runtime مستقل از معماری ثابت بماند.

## گپ‌های غیرقابل‌حل در sandbox (شفاف‌سازی زودهنگام)

1. **آموزش تولیدی**: نیاز به GPU + دیتاست واقعی مجاز دارد؛ در sandbox فقط smoke آموزش واقعی اجرا می‌شود و نیازمندی‌های آموزش اصلی مستند می‌گردد. مدل smoke هرگز «مدل نهایی» معرفی نمی‌شود.
2. **صداهای اختصاصی**: نیازمند ضبط/دیتاست مجاز — پایپ‌لاین و ابزارها ساخته می‌شود، صدای واقعی مشروط به داده است.
3. **آزمون روی دستگاه واقعی Windows/Android**: در sandbox لینوکسی ممکن نیست؛ کد cross-platform + export ONNX واقعی + دستورالعمل آزمون تحویل می‌شود و وضعیت «تحویل‌نشده» صادقانه ثبت می‌گردد.
4. **push به GitHub**: نیازمند توکن/کلید کارفرما.
